# Agent instructions — Shechter Lab AI_ELN

If you are an AI agent (Codex CLI, Claude Code, Cowork, Gemini CLI, Cursor,
or similar) working in this repository, read this first. It applies
whatever model or tool you are; that is why it lives in a plain file at the
root rather than in one vendor's config.

## What this is

The lab's research record: one Markdown file with a flat YAML header per
experiment, project, protocol, and sample, in a fixed folder layout. The
complete rules are `docs/CONVENTIONS.md`; the tool that implements them is
`scripts/eln.py`. Markdown is the source of truth; large raw data lives on
institutional storage and is referenced by path; LabArchives is the
archival record, not this repo.

## Layout

```
Experiments/{ID}_{slug}/{1-notes,2-data_raw,3-code,4-data_processed,5-figures}/
Protocols/P_{Name}.md   Samples/{ID}.md   Projects/{ID}.md
Inventory/*.csv         generated by `eln.py index` - never hand-edit
templates/              the four note schemas; the validator treats their keys as the allowed set
scripts/eln.py          the only way records get created
.agents/skills/lab/     skills for working with this record (read the SKILL.md when a task matches)
.agents/skills/vendor/  pinned methodology skills from K-Dense; never edit, see skills.lock.json
```

**The data may not be in this checkout.** If `AI_ELN_ROOT` is set in the
environment, or `~/.ai_eln.json` has a `root`, that is where `Experiments/`
etc. live. Check before assuming paths are repo-relative; pass `--root` if
needed. IDs: experiments `{INITIALS}e{NNNN}`, samples
`{INITIALS}{p|i|a|c|m|t|r|s|g}{NNNN}`, protocols `P_{Name}`, projects named.

**`sandbox/` is fictional.** It holds made-up experiments for practice
(researchers "Alex Example" and "Jordan Example"). Never cite anything in
it as a lab result and never let a search stray into it. Work there only
when the person explicitly asks for the sandbox (`--root sandbox`).

## The tool

```bash
python3 scripts/eln.py find [--project X] [--status s] [--researcher r] [--tag t] [--sample ID] [--protocol ID] [--text q] [--kind sample|protocol|project] [--ids|--json]
python3 scripts/eln.py new experiment --title "..." [--project ID] [--type T] [--protocol P_X] [--samples ID,ID] [--notebook NB..] [--tags meeting]
python3 scripts/eln.py new sample --type plasmid --title "..."   |  new protocol --name X  |  new project --id X
python3 scripts/eln.py validate [--strict]      # every rule in CONVENTIONS.md; ERROR fails, WARN advises
python3 scripts/eln.py index                    # regenerate Inventory/*.csv
python3 scripts/eln.py report                   # lab-meeting brief from tags: [meeting]
python3 scripts/eln.py export --project X       # bundle for pasting into a chat
```

## Ground rules

1. **Cite experiment IDs.** Every factual claim about a lab result names
   the experiment(s) it comes from. If no note supports it, say so; do not
   fill the gap with a plausible guess.
2. **Never fabricate data, figures, numbers, or experiments.** Drafts of
   Results, summaries, and project pages use only what is written in the
   notes you were pointed at or found.
3. **Filter before reading.** Use `eln.py find` and `Inventory/*.csv` to
   narrow by header fields, then open only the matching notes. The vault is
   meant to outgrow one context window.
4. **Create records only with `eln.py new ...`.** It assigns IDs, builds
   folders, snapshots the protocol, and re-indexes. A hand-made folder
   breaks the ID sequence. If the person has no config yet, run
   `eln.py init --initials XXX --researcher "Name"` first.
5. **`2-data_raw/` is immutable.** Never edit, rename, or reorganize
   anything in it. Derived files go in `4-data_processed/`, named
   `{ID}_{description}`.
6. **Match the schema.** New notes follow `templates/*.md`; header keys
   outside the template are flagged by the validator. If a field is
   genuinely missing, propose a template change rather than an ad hoc key.
7. **Ask before bulk edits.** Rewriting headers across many notes,
   renaming folders, or restructuring needs a human's confirmation first.
8. **Run `eln.py validate` after editing** and fix what it reports for the
   notes you touched.

## Common requests

| request | do |
|---|---|
| "Create an experiment for ..." | `eln.py new experiment` with what was given; ask for a title if missing; check `--project`/`--protocol`/`--samples` exist first. Skill: `eln-record-experiment`. |
| "What do we know about X" / "which experiments used Y" | `eln.py find`, read the matches, answer with IDs, say plainly if nothing turned up. Skill: `eln-search-and-cite`. |
| "Summarize / update project X" | Read `Projects/X.md` and every experiment with X in `project`; rewrite *Current state* in place, every conclusion cited. Skill: `eln-project-synthesis`. |
| "Write up my results" / "mark it complete" | Fill the named sections from what the person tells you; set `status`/`date_completed`; validate. Skill: `eln-record-experiment`. |
| "Prepare lab meeting" | `eln.py report`; expand from the flagged notes only. |
| Design, statistics, writing, citations | The vendored skills under `.agents/skills/vendor/` apply; they are methodology, and rules 1-2 still hold. |
